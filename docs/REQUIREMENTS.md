# Техническое задание: Сервис управления задачами

**Цель:** Разработать REST API сервис для управления задачами в командах с поддержкой ролевой модели, истории изменений и сложными SQL-запросами.

## 🛠 Обязательный стек технологий
* Go
* MySQL
* Redis
* Docker + Docker Compose
* Git

---

## 🗄 Структура базы данных

В проекте реализован минимум из 6 сущностей и 3+ связей между ними:

1. **Users** (Пользователи)
2. **Teams** (Команды)
3. **Team_members** (Связь пользователь → команда, многие-ко-многим + роль)
4. **Tasks** (Задачи)
5. **Task_history** (История изменений задач / аудит)
6. **Task_comments** (Комментарии к задачам)

### Схема связей (Foreign Keys):
1. `teams.created_by` → `users.id`
2. `team_members.user_id` → `users.id`
3. `team_members.team_id` → `teams.id`
4. `tasks.assignee_id` → `users.id`
5. `tasks.team_id` → `teams.id`
6. `tasks.created_by` → `users.id`
7. `task_history.task_id` → `tasks.id`
8. `task_history.changed_by` → `users.id`
9. `task_comments.task_id` → `tasks.id`
10. `task_comments.user_id` → `users.id`

## 🚀 Основные требования к API

### 1. Регистрация и аутентификация
* `POST /api/v1/register` – регистрация пользователя.
* `POST /api/v1/login` – аутентификация (выдача JWT токена).

### 2. Управление командами
* `POST /api/v1/teams` – создать команду (создатель автоматически становится owner).
* `GET /api/v1/teams` – список команд, в которых состоит текущий пользователь.
* `POST /api/v1/teams/{id}/invite` – пригласить пользователя в команду (доступно только ролям owner/admin).

### 3. Управление задачами
* `POST /api/v1/tasks` – создать задачу (только для членов команды).
* `GET /api/v1/tasks?team_id=1&status=todo&assignee_id=5` – фильтрация задач с поддержкой пагинации.
* `PUT /api/v1/tasks/{id}` – обновить задачу (с валидацией прав доступа).
* `GET /api/v1/tasks/{id}/history` – получить историю изменений конкретной задачи.

## 🧠 Сложные SQL-запросы (Обязательно реализовать)

1. **Запрос с JOIN 3+ таблиц + агрегация**
   > "Получить для каждой команды: название, количество участников, количество задач в статусе `done` за последние 7 дней".
2. **Рекурсивный запрос или подзапрос с оконной функцией**
   > "Получить топ-3 пользователя по количеству созданных задач в каждой команде за месяц".
3. **Запрос с условием по связанным таблицам (Валидация целостности)**
   > "Найти задачи, где `assignee` не является членом команды этой задачи".

## ⚡ Оптимизация (Обязательно)

* **Кеширование в Redis:** список задач команды (TTL 5 мин).
* **Индексы в MySQL:** определить и создать индексы для ускорения работы базы данных.
* **Connection pooling:** настройка пула соединений для БД.
* **Пагинация на уровне БД:** реализовать через LIMIT/OFFSET или cursor-based.

## 🌟 Дополнительные пункты (High-level)

* **Circuit breaker** при вызове внешнего сервиса (реализовать мок "email service" для приглашений).
* **Rate limiting** на эндпоинты (ограничение: 100 запросов/мин на пользователя).
* **Graceful shutdown** сервиса при остановке приложения.
* **Prometheus метрики:** сбор данных о количестве запросов, ошибках и времени ответа (latency).
* **Конфигурация:** управление настройками через config файл (YAML / ENV).
